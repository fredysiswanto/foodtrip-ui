# Debugging Guide - FoodTrip UI

This guide explains how to debug your FoodTrip UI project using VS Code.

## Prerequisites

- Google Chrome installed
- VS Code debugger extension (built-in)
- Project dependencies installed (`pnpm install`)

## Available Debug Configurations

### 1. **Admin App - Debug**

- Launches the admin app dev server on `http://localhost:5173`
- Opens Chrome and attaches the debugger automatically
- Perfect for debugging admin features

**How to use:**

1. Open the Debug panel (Cmd+Shift+D)
2. Select "Admin App - Debug" from the dropdown
3. Press F5 or click the green play button
4. Browser will open and you can set breakpoints

### 2. **Client App - Debug**

- Launches the client app dev server on `http://localhost:5174`
- Opens Chrome and attaches the debugger automatically
- Perfect for debugging client features

**How to use:**

1. Open the Debug panel (Cmd+Shift+D)
2. Select "Client App - Debug" from the dropdown
3. Press F5 or click the green play button
4. Browser will open and you can set breakpoints

### 3. **All Apps - Debug** (Compound Configuration)

- Launches both admin and client apps simultaneously
- Useful when testing app interaction

**How to use:**

1. Open the Debug panel (Cmd+Shift+D)
2. Select "All Apps - Debug" from the dropdown
3. Press F5
4. Both apps will start in separate Chrome windows

### 4. **Attach Configurations**

- Use these if you already have the dev servers running
- Attach debugger to an existing running app

**How to use:**

1. Start the dev server manually: `pnpm dev:admin` or `pnpm dev:client`
2. Open the Debug panel
3. Select "Admin App - Attach" or "Client App - Attach"
4. Press F5 to attach the debugger

## Debugging Features

### Setting Breakpoints

- Click on the line number in VS Code to set a breakpoint
- Breakpoints appear as red dots
- When code reaches a breakpoint, execution pauses
- You can inspect variables in the Debug Console

### Console & Variables

- **Variables Panel**: View local and global variables
- **Watch Panel**: Add specific variables to monitor
- **Debug Console**: Run JavaScript commands while paused
- **Call Stack**: See the execution path

### Common Debugging Tasks

#### Debug a React Component

```typescript
// Add breakpoint in your component
function MyComponent() {
  const value = getSomeValue();  // 👈 Click to set breakpoint here
  return <div>{value}</div>;
}
```

#### Debug a Custom Hook

```typescript
// Set breakpoint inside hook
function useMyHook() {
  const [state, setState] = useState(null); // 👈 Breakpoint here
  return state;
}
```

#### Debug API Calls (React Query)

```typescript
// Set breakpoint in hook that uses React Query
function useFoodList() {
  return useQuery({
    queryKey: ['food', 'list'],
    queryFn: async () => {
      const data = await foodAPI.list(); // 👈 Breakpoint here
      return data;
    },
  });
}
```

## Source Maps

- Both apps have source maps enabled in development
- This allows you to debug TypeScript directly (no need to look at compiled JS)
- Source maps are automatically generated by Vite

## Tips & Tricks

1. **Conditional Breakpoints**: Right-click a breakpoint, add condition (e.g., `userId === 123`)
2. **Log Points**: Right-click line number, select "Add Logpoint" for console.log without code changes
3. **Network Inspector**: Use Chrome DevTools (F12) for network debugging alongside VS Code debugger
4. **React DevTools**: Install React DevTools Chrome extension for component debugging

## Troubleshooting

### Debugger doesn't stop at breakpoints

- Ensure source maps are enabled in `vite.config.ts`
- Check that Vite dev server is running (`pnpm dev:admin` or `pnpm dev:client`)
- Refresh the browser (Cmd+R)

### Multiple Chrome instances open

- This is normal when using different debug configs
- You can have one per app open simultaneously

### Port already in use

- Admin app uses port `5173` (update in vite.config.ts if needed)
- Client app uses port `5174` (update in vite.config.ts if needed)
